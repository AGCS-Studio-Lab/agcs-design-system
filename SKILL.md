Read the README.md file within this skill, and explore the other available files.

**Before writing any copy** -- a slide title, an email, a report, a board label -- read `writing.md`. It is the single copy of the voice and report standard: the hard prohibitions (antithetical construction, explaining one thing by leaning on another, acronyms the client has not used, emoji), the language split (English titles and subtitles, Spanish body), the source-marking rules for every figure, and the fixed structure of an AGCS report.

**Nothing leaves this repo as authored HTML.** The slides link external CSS, load JavaScript and declare fonts at relative paths, so a downloaded file loses the grid and the subtitle stops being Crimson Pro SemiBold Italic. Run `python3 tools/build-export.py slides/*.html` and hand over what it writes to `dist/`.

If creating visual artifacts (slides, mocks, throwaway prototypes, etc), copy assets out and create static HTML files for the user to view. If working on production code, you can copy assets and read the rules here to become an expert in designing with this brand.

If the user invokes this skill without any other guidance, ask them what they want to build or design, ask some questions, and act as an expert designer who outputs HTML artifacts _or_ production code, depending on the need.

## Hard constraints (do not violate)

1. **Color is restricted.** Core: Obsidian `#000000`, Paper `#FFFFFF`, **Lime `#C8FF29`** (v3, applied 2026-08-27; legacy v2 `#BEFF3A`. Must equal the icon library, whose baked PNGs were regenerated to this value), Carbon `#1A1A1A`, Mist `#E5E5E5`. **v3 functional palette (2026-07-20), role-bound and exact:** Data blue `#00A1F1` (data viz / system / information layers), Signal yellow `#FFFF00` (warnings / attention), Signal red `#ED1C24` (risk / critical / blockers). Functional colors are never decorative. **Any OTHER blue, green, amber, red, purple, or any gradient stays off-brand** -- decorative blues still put AGCS in the McKinsey / BCG / Deloitte cluster.
2. **Every slide carries EXACTLY ONE lime element -- never zero, never two.** This is a floor before it is a ceiling: **a slide with no lime is a defect**, exactly as much as a slide with two. Before shipping any deck, page through it and confirm every single slide has its lime. The one element is the thing the eye should land on: the topic icon, OR one chart bar, OR one table cell, OR one numerical callout, OR one diagram node. Never as background, body text, or decoration.
   - **If a slide has nothing that deserves the accent, the lime is the topic icon** (`verde1/` colorway) -- that is the default carrier, and it is why the icon library ships in lime. A slide of pure text still gets its lime icon.
   - **The eyebrow chip is exempt.** `.chip-lime` (`RESULTS`, `WHAT'S NEXT`) is a tag that classifies the slide, not an accent competing for attention. A slide may carry one lime chip *and* one lime focus element -- that is the cover pattern. It may never carry two focus elements.
   - Practically: chip + lime topic icon = correct. Lime chart bar + lime topic icon = wrong, the icon goes `negro/`.
3. **Titulo = N27** (Bold 700, Medium 500; Regular 400 is reserve). **Sub titulo = Crimson Pro SEMIBOLD ITALIC (600)** -- v5, ruled 2026-09-02. Every subtitle in the system is this: the deck line under a cover or sign-off title (`.deck-line`), the one-line conclusion under a divider or content title (`.subtitle` / `.agcs-h2`). Never Plex Sans (v3, retired), never N27 Medium, never mono, never Regular weight. **Texto / data / labels = IBM Plex Mono** (Regular 400, Medium 500). **Crimson Pro Italic 400 = the pull quote only** (quote layout). One reflective line per slide, never body copy, never labels. All families load LOCALLY via `@font-face` from `fonts/` -- zero CDN. The system is monospace-dominant.
4. **The Insight slide line-height is `0.92`** -- descenders intentionally touch cap-height below. Do not "fix" this.
5. **No emoji, no third-party icon sets (Lucide, Heroicons, Material, SF Symbols), no decorative SVG.** The chevron `>>` (typed mono) is the only repeating glyph in text. When iconography is required, use **only** the proprietary AGCS icon library in `assets/icons/` -- see the *Iconography* section of README.md. On slides, an icon in the `verde1` (lime) colorway counts as the slide's single Lime element.
6. **Zero radius, zero shadow.** Hierarchy comes from whitespace, ground inversion (Paper ↔ Obsidian) and the construction grid — never elevation.
7. **The construction grid is an accent, not a wallpaper.** 40px step, **3px line, `rgba(0,0,0,.09)` on Paper and `rgba(255,255,255,.11)` on Obsidian** (v5.2, 2026-09-08), full-bleed, **written as literal gradients at the point of use -- never through `var()`**. It goes on the **divider** and on **any slide carrying a chart, a table or a diagram** -- `has-grid` on Divider, Content *with a chart*, System, Build, Next steps -- **and nowhere else**. The **journey matrix is the one documented exception**: it is a table, but it is already a grid, and a construction grid behind it is a second grid that will not align -- the maps in `journey-lab/` are flat. **Flat, by rule:** the five silence slides (Cover, Insight, Quote, End, Logo) **and text-only Content**, which is most of a real deck. The register does not change this: `reg-lab` no longer adds a grid of its own. If you are about to put the grid on a slide with no quantity on it, don't -- that is the v5 defect this rule replaces, where "every layout but five" meant every slide in practice. The grid is only honest when things land on its lines, so on a grid slide: **header hairlines sit on a grid line** (`--band-section: 640px`, `--band-content: 480px`); **chart baselines sit on a grid line and bar heights are whole 80px steps** (round the values, see `slides/03-content.html`); **dense tables sit on a solid Paper panel** with their top edge on a grid line (`.jm`); **boxes carry a solid ground fill** (nodes, step cards). A chart with un-snapped bars over the grid reads as a false scale, which is the defect to avoid. Never paint an inline `background:` on `.agcs-canvas`. **Two things about the line are export rules, not taste:** the canvas is 3840 and is always seen scaled (0.33 at 1280, 0.5 at 1920), so v5.1's 2px at 4.5% resolved to a two-thirds-of-a-pixel line at 3% alpha and disappeared from every download; and the static renderer that turns HTML into Express or a PDF declares that `var(--...)` may not resolve, so a grid built out of nested variables exported as a blank ground. Both are fixed in `colors_and_type.css` and `slides/_slide.css`, and the values are deliberately written twice -- the point of use may not depend on a variable.
8. **Canvas is 4K 16:9 (3840x2160)** for slides.
9. **There is no header band.** Content and divider slides are Paper with the grid; the title sits in the header region above a 1px Mist hairline. The Obsidian band of v2-v4 never appeared in a delivered deck and was removed in v5 (2026-09-02). Never fill `.band`, never draw a black block across the top of a slide.
10. **Every slide picks a register** with one class on `.agcs-canvas`: `reg-studio` or `reg-lab`. Never fork a layout to change register. Both registers share ground, grid, geometry and type, and both follow the same grid rule (rule 7) -- the register is carried by the top-right slot alone: page number in Studio, `>> LAB · v[N]` stamp in Lab.
   - **Studio** (`reg-studio`) -- page number top-right. The client-facing deck.
   - **Lab** (`reg-lab`) -- `>> LAB - v[N]` stamp top-right, heavier mono in headings. The scaffolding is named, not painted.
11. **A slide without a data visual carries one topic icon on the right; a slide with a chart, table or diagram carries none.** Cover, divider, text-only content, insight and next steps take the icon, and it must relate to what that slide argues -- never a generic mark. Content with a chart, journey map, system and build have no icon: the data is the visual, and an icon beside a chart is a second subject.
   - The **system** owns the slot: `class="topic-icon"`, right margin `--pad-slide`, 640px default (`--icon-size` to override), `.is-hero` for the oversized cover treatment.
   - The **deck** owns the choice, and makes it from **`assets/icons/INDEX.md`** -- the catalogue of all 61 icons with what each one means. Read it before placing any icon.
   - **The cover icon is chosen fresh for every deck.** It is the deck's subject: a journey deck takes the eye-with-arrow (`alxgdo/19`), a culture deck the spiral (`22`), a foresight deck the telescope (`18`), a lab program the flask (`01`), a decision deck the fork (`17`). There is **no default cover icon**: `alxgdo/12` and the document-and-arrow glyph (`icons-grid/08`, `agcs_lab_icon_*.svg`) are two icons among 61, not the brand's. Using the same cover icon on consecutive decks is a defect.
   - **No icon repeats inside a deck.** Cover, dividers and content slides each take a different icon. Rotate through the three sets (`alxgdo`, `icons-grid`, `new-icons`).
   - **Colorway follows the ground, not taste:** `negro/` on Paper, `blanco/` on Obsidian, and `verde1/` **only when nothing else on the slide is lime** -- a lime icon *is* the slide's single lime element (rule 2). A slide with a lime chart bar takes a `negro/` icon.

## Key files in this skill

- `README.md` -- voice, visual foundations, font substitutions, iconography rules.
- `ui/` -- **the product-UI layer (v3)**: portable brand primitives (`chevron.jsx`, `brand-footer.jsx`, `lab-stamp.jsx`, `brand-icon.jsx`) that product apps vendor into `src/components/brand/`. See `ui/README.md` for the vendoring contract.
- `ux-rules.md` -- canonical UX & accessibility rules for product apps (states, dataviz, hierarchy without elevation, forms/gates). Subordinate to the brand rules above.
- `colors_and_type.css` -- drop-in stylesheet with all tokens (`--obsidian`, `--lime`, `--font-mono`, `--t-insight`, ...) and semantic classes (`.agcs-insight`, `.agcs-quote`, `.agcs-label`).
- `assets/agcs_mark_{white,black}.svg` -- **the AGCS mark**, used at size on the logo slide only. **Only white on Obsidian or black on Paper.** Never lime, never on a colored ground. Note `assets/agcs_lab_icon_*.svg` are NOT the mark: all four hold the same document-and-arrow *topic icon*.
- `assets/icons/` -- the proprietary AGCS icon library: `alxgdo/` (34 line icons in negro / blanco / verde1-lime / verde2 / verde3 + `animation.gif`), `icons-grid/` (16 icons drawn on the construction grid, 4 colorways), `new-icons/` (11 newer icons, 4 colorways), `grid-templates/` (14 construction grids + principal, black & white), `_source/ICONOS.pdf`. New work uses **negro on Paper, blanco on Obsidian, verde1 as the one lime accent**.
- `assets/icons/INDEX.md` -- **the icon catalogue**: every icon by number with its subject and the arguments it can stand for. The cover icon and every slide icon are picked from here.
- `slides/01-cover.html` ... `slides/07-system-lab.html` -- the 7 canonical layouts. Copy and adapt; don't re-invent.
- `slides/index.html` -- flip through all 7 in a deck-stage shell.
- `journey-lab/` -- **the customer-journey method**, not just the map slide: `journey.css` plus 7 compositions (AS-IS map, TO-BE map, validated TO-BE v2, group readout, four-group overview, JTBD forces + job story, DVFR validation step) covering a three-day lab. `journey-lab/README.md` has the method, the per-composition lime doctrine and the typical mistakes. This is the only journey map in the system: the old `slides/08-journey-map.html` was retired, so there is no lighter second version to reach for.

## Voice cheatsheet

- Conclusion-first headlines. "X is true," not "we believe X."
- 2-3 line paragraphs in mono. Numbers are evidence, never decoration.
- Sentence case in body. ALL CAPS allowed only in short mono labels (`INTRO`, `SYNTHESIS`, `Q1`, `>> LAB · V03`).
- Spanish-primary; quoted English thinkers stay in English.
- Tagline: `>> Stay Forward`. Attribution: `AGCS | Studio + Lab |` (spaces around `+`).
